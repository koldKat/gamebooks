Access

Open http://localhost:3000/admin (or https://localhost/admin if TLS is active) in a browser on the same machine as the server.

All /api/admin/* routes and the panel itself reject any connection that is not from localhost (127.0.0.1, ::1, or ::ffff:127.0.0.1). No login is required - the localhost restriction is the sole access control. X-Forwarded-For and similar proxy headers are never trusted for this check.

Stats for Nerds

An expandable section below the main cards showing deeper aggregate counts:

  • Users: total accounts, admins count, undos performed (sum of undosUsed across all active play state), fast travels performed
  • Books / Series / Anthologies: separate unique-count and library-count totals
  • Gameplay: total runs, finished runs, wins, losses, battle deaths
  • XP events: total XP event records, number of distinct event types
  • Gold Coins & Shop: earned/spent/in-circulation totals plus purchased upgrades, including Heartbeat XP; in-circulation totals also include extra milestone GC rewards
  • Books: includes unique authors and average sections per playable book in the detailed breakdown
  • Forum: total posts (active only - excludes deleted), total threads (active only)

Vacuum Database purges all expired sessions, then rewrites the database file to reclaim unused space. Stats cards refresh automatically afterwards.

Users tab

Lists all registered accounts. Columns: Username, Joined, Last Active, Days Inactive, Books, Runs, Wins, Losses, Level, Sessions, Location, Domain, Actions.

Badges visible in the Username column:

  • ADMIN - account has is_admin = 1 (full admin privileges)
  • PROTECTED - account has is_protected = 1 (cannot be deleted or locked; used for safety accounts like the demo user)
  • AUTHOR - account has is_author = 1 (shown a special badge in the public app)
  • CONTRIBUTOR - account has is_contributor = 1
  • LOCKED - account is currently locked (login denied until an admin unlocks it)

The Location column shows the country flag and approximate city recorded at the user's most recent login, resolved via the geoip-lite offline database. Hovering the flag shows the full country name. Blank (-) until first login after geo support was added.

The Domain column shows which of the app's domains (e.g. koldkat.net / pathmap.net / bookplay.net) the user was last seen on, read straight from the Host header on their most recent authenticated request (last_domain column, blank/- until their first request after this was added). A leading www. is stripped for display. Unlike Location, there's no time-based throttle on this - it's cheap to skip since the write is a no-op whenever the domain hasn't changed since last recorded.

Clicking a username opens the user detail view, showing a meta bar (Joined, Books, Sessions, Last Location, Domain, Level) and a table of all their books with per-book stats.

User actions

Each row in the Users table has an Actions column. Available actions depend on whether the account is protected or locked.

Clear sessions

Invalidates all active sessions for that user - forces logout on every device immediately. Does not lock the account; the user can log back in straight away.

Lock / Unlock

Lock - sets locked_until to a far-future date, preventing login. The user sees an "account locked" message. Protected accounts (is_protected = 1) cannot be locked.

Unlock - clears locked_until, restoring login access immediately.

Set Author / Contributor flags

Clicking Author opens a small form to toggle is_author and optionally set a display_name (shown in the public app instead of the username). Clicking Contributor toggles is_contributor. Both flags control the badge displayed in the public app and are independent of admin privileges.

Edit user

Allows the admin to directly update the user's username, display_name, is_admin, is_protected, is_author, and is_contributor fields without going through the user-facing profile flow.

Impersonate

Generates a one-time impersonation token and returns a URL (/auth/impersonate?token=…) derived from the request's Host header, so the link always points to the correct server (including shadow or staging instances). Opening that URL logs in as the target user without needing their password. The token is single-use and expires after a short window. Useful for reproducing user-reported bugs.

The impersonation URL must be opened in a browser that can reach the app at the same host. The token is not tied to an IP. Treat it as a temporary credential.

Grant / Revoke PDF Access

Toggles the pdf_access flag for the user. When granted, the user can download book PDFs via GET /books/:path and sees a small PDF link in the play area when a book has a PDF attached. The button label switches between Grant PDF Access and Revoke PDF Access depending on the current state. Admins always have implicit PDF access regardless of this flag.

Refund shop item

Opens a form to refund a purchased shop item for the user. Specify the item key (e.g. xp_boost, heartbeat_xp, undo, fast_travel) and whether to refund all purchases of that item or only the most recent. Coins are returned; any stat changes from the item are reversed.

Delete

Permanently removes the user and all their books, runs, notebook data, and sessions (cascades). Requires confirmation dialog. Protected accounts (is_protected = 1) cannot be deleted.

Books tab

Lists every non-demo, non-container book across all users (standalone books and anthology children - anthology containers themselves are listed separately in the Anthologies tab, since a container has no playthroughs of its own). Columns: Book, Owner, Sections, Wins, Losses, Last Updated, Actions. Paginated at 50 rows/page.

Clicking a book name opens the book detail view:

  • Stats - section count, run counts, wins/losses; full playthroughs table with username, start date, outcome
  • Ratings - all ratings submitted for this book, with username, score, and a delete button per rating
  • PDF - upload a PDF (raw body, max 128 MB, must start with %PDF magic bytes). Awards 200 XP to every user who has the book in their library at the time of upload. A delete button removes the PDF (XP not revoked). Existing PDFs open in a new browser tab from the current-PDF link.

The Edit button opens an inline form with all metadata fields:

  • Name, Total Sections, Pages, ISBN / ASIN / ISSN, Author(s), Description
  • Make public - is_public toggle
  • Is anthology (container) - marks this book as a parent container; total_sections is stored as 0
  • Series - text input with datalist autocomplete; resolved to series_id on save
  • Note - unlike the main app, which shows users only their own series in the edit dropdowns, the admin panel intentionally exposes the global series list here.
  • # in series - free text (e.g. 12 or XII)
  • Part of anthology - dropdown of all container books; links this book as a child
  • Order - integer sort position within the parent anthology
  • Cover - upload or remove cover image

Reset semantics: the normal in-app Reset Book flow does not revoke XP. It clears the saved book state and run history for that user/book while also clearing only the per-book progress XP locks so reruns can earn progress XP again.

Series tab

Lists all series in the database with creator username, book count, public status, created date, and description. Paginated at 50 rows/page.

Edit - opens an inline edit row (no navigation required) to update the series name, description, and public flag.

Delete - removes the series entirely: orphans all linked books (series_id = NULL), removes all user_series rows, and deletes the series row. Requires confirmation. This is irreversible.

Deleting a series from here affects all users who had it in their library. Use with care.

Anthologies tab

Lists all anthology container books (is_container = 1) across all users, separate from the Books tab. Columns: Name, Creator, Books (child count), Public, Created, Description, Actions. Paginated at 50 rows/page.

Delete - removes the container row. Children are not deleted - the foreign key automatically orphans them (parent_book_id = NULL) instead. Blocked with the same "still has readers" error as a normal book delete if any user has the container itself in their library. Requires confirmation.

Tips tab

Lists all tips stored in the tips table. Filterable by type (real / silly) and active status. The app alternates real and silly tips in a shuffled deck - only active tips are served.

  • Active checkbox - toggle a tip on or off without deleting it. Saves immediately.
  • Click text - inline edit: replaces the text cell with an input and Save button.
  • → Silly / → Real - flips the type in one click.
  • Delete - permanently removes the tip. Requires confirmation.

The Add New Tip form at the bottom accepts text and a type selector. Duplicate text is rejected.

Book actions

Gift book

Adds a book to another user's library without them having to find or add it themselves. The admin selects a source user (the book's current owner - used to copy state/progress if desired) and a target user. If the target already has the book, the request is rejected with a conflict error. The operation creates a new user_books row for the target user.

The gift is administrative - no XP is awarded to either party as a result of the gift itself.

Delete ratings

From the book detail → Ratings tab, each individual rating can be deleted. This removes the rating value from the user_books row, not the row itself.

Delete book

Permanently removes the book and all associated run data for all users. If any user other than the owner has the book in their library, the deletion is blocked (409 has_readers) - remove all readers first, or use this with care. Requires confirmation.

Feedback tab

Shows all user feedback threads, newest first. Each thread is a conversation between one user and the admin.

A red count badge on the tab header shows how many threads have unread user messages.

Feedback also appears in koldKat's inbox in the main app - the inbox loads all threads and maps admin_unread to the badge count. Replying from either place works the same way; threads with a registered email also trigger an email reply.

Users can attach files to their initial feedback submission and to inbox replies. Attached images appear inline; other files appear as download links - the admin feedback tab renders them the same way now. Admin replies via this tab (POST /api/admin/feedback/:id/reply) still do not support attachments; use koldKat's inbox in the main app for attachment-enabled replies.

Reading feedback

Expanding a thread shows the full message history in chronological order. Each message shows the sender (user or Admin), timestamp, and text. Clicking Mark as read clears the unread highlight and decrements the badge count - this is recorded in feedback_read_at.

Replying

Typing in the reply box and clicking Send appends an admin message to the thread. If SMTP is configured and active, the reply is also emailed to the user's registered email address.

Deleting threads

The Delete button on a thread is a soft delete (deleted_by_admin = 1) - it hides the thread from this tab but does not actually remove the row, its messages, or their attachments from the database.

Announcements tab

Announcements are short notices shown to all users in the main app. They live in the announcements table and go through a draft → published → pinned workflow.

Creating an announcement

Click New Announcement. Fill in the Title and Body (both required). Save creates the announcement in draft state - it is not yet visible to users.

Editing

Draft announcements can be edited freely. Published or pinned announcements can also be edited; the updated content is shown to users immediately.

Publishing / Unpublishing

Publish sets published_at and makes the announcement visible in the app's announcements list. Unpublish removes it from public view (returns to draft state) but does not delete it.

Pinning / Unpinning

A published announcement can be pinned, which marks it with pinned = 1. Pinned announcements are displayed more prominently in the app (e.g. at the top of the list or as a banner). Only one announcement can be pinned at a time - pinning a second one unpins the previous. Unpin clears the pin without unpublishing.

Deleting

Permanently deletes the announcement regardless of its state. This is irreversible.

The admin panel is the only place to create or manage announcements. Do not create announcements on behalf of the user - draft the text and copy it for them to review before publishing.

App-wide XP widget

Shown only when the logged-in account is the admin, a small panel sits above the personal XP summary on the Books screen (in a violet accent to distinguish it from the player's own gold/cyan bar). It mirrors the same shape - level, title, heartbeat rate, XP bar, XP text, boost line - but the numbers are aggregated across every account: total XP earned app-wide (same number Stats for Nerds shows as "Total XP earned", just not compact-formatted), an "app level" scaled by user count (same formula as the "App level" figure in Stats for Nerds), every user's active boost rate added together, and a combined heartbeat rate as if every player were online at once. It refreshes on login, shortly after any site activity (deliberately staggered by ~1.2s so it doesn't animate in lockstep with your own XP bar), and every 60 seconds as a fallback while the tab is visible.

Backed by GET /api/app-xp - token auth plus an admin check, not a localhost-only /api/admin/* route, since it needs to render inside the normal logged-in app rather than the operator-only admin panel.

Live floaters: whenever any other user earns XP or GC, a small floater pops up showing their username and the amount, in the same violet/pink theme, centered between the activity feed and the covers panel. Only shown on the Books screen, and only for other users - the admin's own gains still show through their normal personal floaters. Backed by GET /api/app-xp/stream, an admin-only SSE stream.

Avg User Level widget

Sits directly above the App-wide XP widget, same shape again but in teal/lime. Unlike the App widget's level (a single pooled-XP figure that a few high-XP users can skew upward), this is the average of each user's own level - the same metric behind Stats for Nerds' "Avg player level" figure. The top-right tag shows total user count instead of a heartbeat rate. The bar fill shows how close the whole app is to ticking the average level up by one (the fractional part of the raw average, e.g. 1.98 → 98% full). The text line shows the sum of every user's level and exactly how many more total levels need to be gained by anyone to cross into the next average level. The bottom line shows the lowest-to-highest level spread across all users. It doesn't animate like the other two bars - it only moves on an actual level-up and by a tiny amount, so it just snaps to the new value.

SMTP / email configuration

Email is used for admin replies to feedback threads. All settings are stored in the admin_settings table and override any equivalent .env variables. Changes take effect immediately - no restart required.

SettingDefaultDescription
smtp_hostenv SMTP_HOSTSMTP server hostname (e.g. smtp.gmail.com)
smtp_port465SMTP port. 465 for implicit TLS; 587 for STARTTLS.
smtp_securetrueSet to true for implicit TLS (port 465). Set to false for STARTTLS (port 587).
smtp_userenv SMTP_USERLogin username for the SMTP server. Also used as the default To address for SMTP test emails.
smtp_fromfalls back to smtp_userFrom address used in outbound emails (e.g. noreply@example.com). Defaults to smtp_user if blank.
smtp_passenv SMTP_PASSSMTP password or app-specific password. Saving an empty string is a no-op (keeps the existing password). To clear the password, use db.setAdminSetting directly.

The Test SMTP button sends a test email to smtp_user using the current transporter. The status indicator next to the SMTP section header shows whether a transporter is currently active (green = active, red = not configured or credentials missing).

The transporter is re-initialised automatically whenever any smtp_* setting is saved.

SMTP credentials can also be provided via .env variables (SMTP_HOST, SMTP_PORT, SMTP_SECURE, SMTP_USER, SMTP_PASS, SMTP_FROM). DB settings take precedence over env variables when both are set.
